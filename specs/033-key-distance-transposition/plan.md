# Implementation Plan: Key-Distance Enharmonic Spelling for Transposition

**Branch**: `033-key-distance-transposition` (work is on `main`; no feature branch was created) | **Date**: 2026-10-27 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/033-key-distance-transposition/spec.md`

## Summary

Replace the `SmoMusic.enharmonicRoles` table in [music.ts](../../src/smo/data/music.ts) and the role lookups built on it with arithmetic on the circle of fifths. Every spelling gets a single integer position on the "line of fifths" (F=-1, C=0, G=1 ... B=5, plus 7 per sharp, minus 7 per flat) and every major key signature gets an index in -7..+7. From those two numbers:

- a key's seven scale tones are the positions `k-1 .. k+5`;
- a spelling's signed *distance* from a key is how far it lies outside that window (A# in C: 5 sharps; Bb in C: 1 flat);
- the default spelling of a pitch class is the candidate with the smallest distance, ties going to the flat side;
- transposing from key `ks` to key `kd` shifts every position by `kd - ks`, which preserves scale degree, alteration and therefore distance exactly.

The whole-score transpose operation computes the destination key from the interval and applies that shift. No serialization changes.

## Technical Context

**Language/Version**: TypeScript (see `tsconfig.json`), run in tests with `ts-node`

**Primary Dependencies**: None new. VexFlow is not involved in the spelling logic; `SmoMusic` helpers (`smoPitchToInt`, `smoIntToPitch`, `noteValues`) are reused.

**Storage**: N/A. Pitches serialize as `{letter, accidental, octave}` and key signatures as lowercase VexFlow strings (`'c'`, `'db'`, `'f#'`); both are unchanged.

**Testing**: Headless `ts-node` scripts under `tests/`, one npm script each (see `test:voice-copy-paste`). New: `tests/keyDistanceTransposition.ts` with script `test:key-distance-transposition`.

**Target Platform**: Browser application and library (`src/smo` has no UI dependencies).

**Project Type**: Single project (TypeScript library plus Vue UI).

**Performance Goals**: Spelling is O(1) per pitch (a few integer operations); the table lookup it replaces was a linear scan. No rendering impact.

**Constraints**: Sounding pitch must never change when respelling (FR-010). Output must stay within double sharps/flats, which the existing `noteValues` table supports.

**Scale/Scope**: One module (`music.ts`), three callers' behavior (`SmoNote.transpose`, chord-symbol transposition, `SmoOperation.transpose`/`transposeScore`), one new test file.
